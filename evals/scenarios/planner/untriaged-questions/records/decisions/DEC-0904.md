# DEC-0904: Export output filenames include a timestamp

## Context

An export job can run more than once for the same connector on the same day (a manual re-run after a fix, or a
retried schedule). A fixed filename with no timestamp means a later run silently overwrites an earlier one's
output.

## Decision

Every export job's output filename includes the run's start timestamp.

## Rationale

A timestamped filename keeps every run's output on disk independently, so a re-run never destroys evidence of
an earlier run without anyone deciding to delete it.

## Consequences

Any job that reads export output by a fixed, predictable filename must instead read the most recent
timestamped file for its connector.

## Alternatives Considered

- **Fixed filename, always overwritten.** Rejected: silently destroys the previous run's output.
- **A separate directory per run instead of a timestamp in the name.** Rejected: more moving parts than a
  timestamp in the filename, for no gain here.
