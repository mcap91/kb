# WK-0903: Frontmatter parser does not support nested YAML

## Objective

The repo's frontmatter parser reads only flat scalars and flat arrays out of a record's frontmatter block. A
frontmatter field that holds a list of maps (nested YAML) comes back wrong — keys from the nested maps leak
into the flat field set instead of staying nested.

## Scope

- Track the parser gap. Fixing the parser is its own, separate piece of work; nothing here changes parser
  behavior.

## Checklist

- [ ] Reproduce the nested-list misparse with one example record
- [ ] File the parser fix as its own follow-up

## Acceptance criteria

- [ ] A reproduction record and a written description of the misparse exist, so a future parser fix has a
  concrete case to check against

## Notes

Found while scoping [[WK-0902]]: a connector record that tried a nested frontmatter list for its stages came
back with the nested keys flattened into the record's top-level fields.
