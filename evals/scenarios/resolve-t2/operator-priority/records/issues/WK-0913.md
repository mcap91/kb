# WK-0913: Add an idempotency key to checkout retries

## Objective

A checkout retry after a timeout can charge a customer twice when the first attempt actually succeeded.
Add an idempotency key so a retried checkout never double-charges.

## Scope

- The checkout endpoint accepts and honors an idempotency key on retry.
- Out: anything about how or when a client decides to retry.

## Open Questions

- Which should we build first: this work, or WK-0914 (the checkout-abandonment reminder email)?

## Acceptance criteria
