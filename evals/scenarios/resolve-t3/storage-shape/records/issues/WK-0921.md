# WK-0921: Read each pipeline's step list when the scheduler runs

## Objective

Each pipeline record names an ordered list of steps (e.g. fetch, validate, publish) the scheduler must run
in order. No code in this repo currently reads that list.

## Scope

- Add the read path the scheduler uses to load one pipeline's step list before it runs.
- Out: changing what a step does once it is read.

## Open Questions

- Should the step list live in nested frontmatter YAML or in a body table?

## Checklist

- [ ] Resolve where the step list lives before writing the reader
- [ ] Add the reader and a test covering one pipeline

## Acceptance criteria

- [ ] The scheduler reads a pipeline's step list and runs its steps in order, covered by a test
- [ ] The `## Resolutions` row for the storage-shape question cites the record that settles it
