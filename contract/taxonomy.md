# Record Type Taxonomy

This document describes the taxonomy of record types in the `kb` wiki system and their relationships.

## Manifest-Driven Record Types

These are the record types managed by `wiki-core`. They are defined in `contract/manifest.json` and are valid targets for `wiki create`, lint, generate, and search.

### WK-* Work Items

Work items track individual units of work: bugs, features, tasks, investigations, chores, documentation, infrastructure, and migrations.

- **ID format:** `WK-NNNN` (allocated sequential)
- **Directory:** `wiki/issues/`
- **Relationships:** depends_on, blocks, related, area, initiative
- **Code linkage:** repo_paths, docs

### IN-* Initiatives

Initiatives are higher-level groupings that organize multiple work items toward a common goal.

- **ID format:** `IN-NNNN` (allocated sequential)
- **Directory:** `wiki/initiatives/`
- **Relationships:** depends_on, blocks, related, area
- **Contains:** work items via initiative reference

### DEC-* Decisions

Decisions record architectural and design choices with their rationale and status.

- **ID format:** `DEC-NNNN` (allocated sequential)
- **Directory:** `wiki/decisions/`
- **Relationships:** related, supersedes/superseded_by, area
- **Lifecycle:** proposed -> accepted | rejected | superseded | deprecated

### SRC-* Sources

Sources capture external references: papers, articles, repositories, and other materials that inform work.

- **ID format:** `SRC-NNNN` (allocated sequential)
- **Directory:** `wiki/sources/`
- **Relationships:** related_docs, related_work
- **Key fields:** source_uri, authority, immutable_hint

### AREA Records

Areas define functional domains within a project. They serve as the primary organizational axis.

- **ID format:** slug-based (e.g. `tooling`, `architecture`)
- **Directory:** `wiki/areas/`
- **Relationships:** initiatives, sources, decisions, related
- **Role:** grouping and navigation

## Dispatch-Owned Record Types

These record types exist in the wiki directory structure but are owned and managed by `dispatch-core`, not `wiki-core`.

### HO-* Handoffs

Handoff records define work packages for multi-agent dispatch. They specify what an agent should do, which agents are allowed, and what scope constraints apply.

- **ID format:** `HO-NNNN` (allocated by author, not by wiki-core)
- **Directory:** `wiki/handoffs/`
- **Owner:** `dispatch-core`
- **Not valid for:** `wiki create`, `wiki lint`, `wiki generate`, `wiki search` (in MVP)
- **Template:** `contract/templates/handoff.md` (synced as shared template surface)

## Relationship Graph

```
AREA
 ├── IN-* (initiatives in this area)
 │    └── WK-* (work items in this initiative)
 ├── DEC-* (decisions in this area)
 └── SRC-* (sources in this area)

WK-* ──depends_on──> WK-*
WK-* ──blocks──────> WK-*
WK-* ──related─────> WK-*, IN-*, DEC-*, SRC-*
WK-* ──repo_paths──> code files
WK-* ──docs────────> doc files
```

## Generated Views

Generated views aggregate manifest-driven records into navigable summaries. They are non-canonical and regenerated by `wiki generate`:

| View | Content |
|------|---------|
| `wiki/catalog.md` | Full record catalog |
| `wiki/now.md` | Active work (in_progress, review) |
| `wiki/inbox.md` | Inbox items awaiting triage |
| `wiki/backlog.md` | Todo and parked items |
| `wiki/archive.md` | Completed and closed items |
