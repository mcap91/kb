# Conventions

This document defines naming, ID format, file organization, and operational conventions for wiki records managed by `kb`.

## Record Prefixes

| Prefix | Type | ID Strategy | Directory |
|--------|------|-------------|-----------|
| `WK` | Work item | Allocated sequential | `wiki/issues/` |
| `IN` | Initiative | Allocated sequential | `wiki/initiatives/` |
| `DEC` | Decision | Allocated sequential | `wiki/decisions/` |
| `SRC` | Source | Allocated sequential | `wiki/sources/` |
| `AREA` | Area | Slug-based | `wiki/areas/` |

### Dispatch-Owned Prefixes

| Prefix | Type | Directory | Owner |
|--------|------|-----------|-------|
| `HO` | Handoff | `wiki/handoffs/` | `dispatch-core` |

> **Important:** `HO-*` records are **dispatch-owned**, not manifest-driven wiki record types. They are not valid targets for `wiki create` in MVP. The handoff template (`contract/templates/handoff.md`) is synced as a shared template surface, but handoff records are authored manually and validated by `dispatch-core`.

## ID Format

### Allocated IDs

Allocated IDs use zero-padded 4-digit sequential numbers:

- `WK-0001`, `WK-0002`, ...
- `IN-0001`, `IN-0002`, ...
- `DEC-0001`, `DEC-0002`, ...
- `SRC-0001`, `SRC-0002`, ...
- `HO-0001`, `HO-0002`, ... (dispatch-owned)

### Slug IDs

Area records use human-readable slug identifiers:

- `tooling`, `architecture`, `testing`, ...

Slug rules:
- lowercase
- alphanumeric and hyphens only
- no leading or trailing hyphens
- no consecutive hyphens

## File Naming

### Allocated Records

Files are named by ID only: `WK-0001.md`, `IN-0001.md`, etc.

### Slug Records

Area files are named by slug: `tooling.md`, `architecture.md`, etc.

### Reserved Filenames

Each record directory reserves `README.md` for optional directory-level documentation.

## File Organization

```
wiki/
  .wiki-contract.json     # Contract metadata (runtime)
  .id-state.json          # ID allocator state (runtime)
  schema.md               # Schema reference (consumer-owned after bootstrap)
  conventions.md          # Conventions (consumer-owned after bootstrap)
  index.md                # Wiki index (consumer-owned after bootstrap)
  catalog.md              # Generated view
  now.md                  # Generated view
  inbox.md                # Generated view
  backlog.md              # Generated view
  archive.md              # Generated view
  issues/                 # WK-* work items
  initiatives/            # IN-* initiatives
  decisions/              # DEC-* decisions
  sources/                # SRC-* sources
  areas/                  # AREA records
  handoffs/               # HO-* handoffs (dispatch-owned)
```

## Frontmatter Format

All wiki records use YAML frontmatter delimited by `---`:

```yaml
---
id: WK-0001
title: Example work item
type: task
status: todo
priority: medium
owner: user
created: 2026-01-01
updated: 2026-01-01
---

# WK-0001: Example work item

Body content here.
```

## Date Format

All dates use ISO 8601 format: `YYYY-MM-DD` or full ISO datetime.

## Cross-Repo References

Cross-repo record references use the format: `org/repo:WK-0001`

Cross-repo path references use the format: `org/repo/wiki/<surface>/<file>.md`

## Generated Views

Generated views are non-canonical and are regenerated by `wiki generate`. They include a frontmatter marker indicating they are generated:

```yaml
---
generated: true
generated_at: 2026-01-01T00:00:00Z
---
```

Generated views are excluded from search indexing and lint.
