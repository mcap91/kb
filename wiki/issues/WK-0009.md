# WK-0009: Define the PLN bundle layout and adapter contract

## Description

Define the filesystem layout and machine-readable metadata that sit under each `PLN-*` record. The
bundle contract should let `kb` own a normalized design/execution package while preserving raw
upstream artifacts from Superpowers today and any future planning producer later. This is the
future-proofing boundary that keeps `kb` from hardcoding one specific planning workflow.

## Acceptance Criteria

- [ ] There is a canonical bundle layout under `wiki/plans/PLN-xxxx/` that separates the durable
      plan record from its operational companion material.
- [ ] `bundle.json` or an equivalent manifest defines producer metadata, normalized entrypoints,
      and preserved source artifacts.
- [ ] The contract clearly separates kb-owned normalized artifacts from planner-specific raw input.
- [ ] The bundle design allows Superpowers brainstorming and `plan-me-this` to act as the first
      adapter without making their native file layout the canonical kb layout.

## Notes

- This work is tracked under [IN-0002](../initiatives/IN-0002.md).
- The authoritative feature design is [2026-05-06-pln-design.md](../../docs/superpowers/specs/2026-05-06-pln-design.md).
- The authoritative implementation plan is [2026-05-06-pln-implementation.md](../../docs/superpowers/plans/2026-05-06-pln-implementation.md).
- The adapter boundary must stay generic enough that a future non-Superpowers planner can populate
  the same normalized bundle contract.
