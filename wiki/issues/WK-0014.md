# WK-0014: Align dispatch runtime telemetry with portfolio blackboard protocol

## Description

Align `kb dispatch` runtime behavior with the stronger blackboard launcher model already proven in
`portfolio-wiki-tools`.

The current `kb` launcher was functionally able to spawn child agents, but it stayed blind while
they were running because it buffered stdout/stderr until exit and persisted no live run-state
metadata. That made it difficult to distinguish:

- a real agent hang
- a launcher logging/transport bug
- a stale token/reporting problem

This work brings `kb` to parity on the runtime path: live stdout capture for stdout adapters,
`state.json` with pid/pgid/heartbeat, token consumption after confirmed child start, and status /
cleanup logic that understands active runs separately from token lifecycle.

## Acceptance Criteria

- [x] `dispatch launch` streams stdout-capture adapters into `response.md` while the child is still running
- [x] `dispatch launch` writes `metadata/state.json` with `status`, `pid`, `pgid`, and `heartbeat_at`
- [x] started launches move the review token from `launching/` to `consumed/` immediately after confirmed child start
- [x] empty-response runs fail closed with terminal run status `failed` without leaving the token in `launching/`
- [x] `dispatch status` reports active launches from non-terminal run state, not only from token directories
- [x] `dispatch cleanup` does not recover a launching token while its associated run still looks alive

## Notes

- parity target: `portfolio-wiki-tools` blackboard launcher runtime model
- verified with `npm run typecheck`, `npm test`, `npm run wiki -- generate --dir .`, and `npm run wiki -- lint --dir .`
