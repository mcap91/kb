# WK-0008: Define the PLN record contract, taxonomy, and lifecycle

## Description

Define `PLN-*` as a new manifest-driven wiki record type for design-approved, one-time build
scaffolds. This work should establish the minimal durable record surface, explain why `PLN-*`
exists alongside `IN-*`, `WK-*`, and `HO-*`, and make the lifecycle semantics explicit so future
planning artifacts do not get forced back into the wrong record classes.

## Acceptance Criteria

- [ ] `contract/manifest.json`, templates, and contract docs define `PLN-*` as a first-class
      manifest-driven wiki type.
- [ ] The required and optional fields for `PLN-*` are intentionally thin and durable, with
      execution detail kept out of the record body and delegated to the attached bundle.
- [ ] The lifecycle states make the distinction between planning, active execution, completion, and
      archival explicit.
- [ ] The docs explain that `PLN-*` exists because one-time build scaffolds do not fit cleanly in
      `IN-*` or `WK-*`, and that `PLN-*` is neither a handoff nor a second issue tracker.
