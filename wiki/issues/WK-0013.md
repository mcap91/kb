# WK-0013: dispatch leaves launch.json stuck at launching after terminal runs, causing stale active-launch reporting

## Description

`kb dispatch` can complete or reject a run correctly, but still leaves the run-local
`metadata/launch.json` file at `token_state: "launching"`. Because token/state reporting is
directory-driven, stale launching tokens can then cause `dispatch status` to report active launches
that are not actually running.

This is a state/reporting bug. The agent process itself may have already finished successfully or
failed terminally.

### Environment

- agent: `claude`
- launcher registry: default `launchers.v1.json`

### Confirmed behaviors

#### 1. Successful trivial Claude launch still leaves launch.json at `launching`

Minimal smoke handoff:

```bash
cd /root/kb
npm run dispatch -- review-and-launch \
  --dir /tmp/kb-dispatch-smoke \
  --handoff wiki/handoffs/HO-0001.md \
  --agent claude \
  --reviewed-and-accept-risks
```

Results:

- review id: `RV-8cfcfc7b-aa79-43b2-afc9-42e8dbd923ed`
- run id: `RUN-13d0b94a-20c5-4208-b662-dcbc8a1daeda`
- response: Smoke dispatch OK.

Observed state:

- `response.md` exists
- `metadata/meta.json` says `status: "completed"`
- `metadata/launch.json` still says `token_state: "launching"`

Artifacts:

- `/tmp/kb-dispatch-smoke/.agent-runs/runs/HO-0001/RUN-13d0b94a-20c5-4208-b662-dcbc8a1daeda/response.md`
- `/tmp/kb-dispatch-smoke/.agent-runs/runs/HO-0001/RUN-13d0b94a-20c5-4208-b662-dcbc8a1daeda/metadata/meta.json`
- `/tmp/kb-dispatch-smoke/.agent-runs/runs/HO-0001/RUN-13d0b94a-20c5-4208-b662-dcbc8a1daeda/metadata/launch.json`

#### 2. Failed Claude launch also leaves launch.json at `launching`

Earlier run:

- review id: `RV-ca547c9c-2b24-4d19-910f-ffac3070497c`
- run id: `RUN-51193c4c-0779-414b-b1fc-e69bf5fb0f6d`

Terminal state:

- `metadata/meta.json` says:
  - `status: "rejected"`
  - `exit_code: 143`
  - `error: "Empty agent response"`
- token was moved to `rejected/`

But:

- `metadata/launch.json` still says `token_state: "launching"`

Artifacts:

- `/root/spatial-biology/.agent-runs/runs/HO-0008/RUN-51193c4c-0779-414b-b1fc-e69bf5fb0f6d/metadata/meta.json`
- `/root/spatial-biology/.agent-runs/runs/HO-0008/RUN-51193c4c-0779-414b-b1fc-e69bf5fb0f6d/metadata/launch.json`
- `/root/.config/kb-dispatch/rejected/RV-ca547c9c-2b24-4d19-910f-ffac3070497c.json`

#### 3. dispatch status reports false active launches from stale launching/ tokens

A stale launching token remained for a completed run:

- stale token: `/root/.config/kb-dispatch/launching/RV-09ce82af-51fe-439d-a096-1cbe3ed81b3b.json`
- corresponding completed run metadata:
  - `/root/spatial-biology/.agent-runs/runs/HO-0007/RUN-249b97fa-c85b-43a6-8bbe-875588f1fd17/metadata/meta.json`
  - `status: "completed"`

While that stale token existed, `npm run dispatch -- status --dir /root/spatial-biology` reported
`Active launches: 1` even though no agent process was still running.

Manual fix: moving that token to `consumed/` corrected status to `Active launches: 0`.

## Acceptance Criteria

- [ ] On terminal success, `metadata/launch.json` is rewritten to a final state such as `token_state: "consumed"`
- [ ] On terminal rejection/failure, `metadata/launch.json` is rewritten to `token_state: "rejected"`
- [ ] `dispatch status` does not count stale/terminal launching tokens as active launches
- [ ] Cleanup/status can reconcile a launching token against terminal run metadata

## Likely code areas

- `packages/dispatch-core/src/launch.ts` — writes initial `launch.json`, moves tokens to `consumed/rejected`, writes `meta.json`, but does not appear to finalize `launch.json`
- `packages/dispatch-core/src/status.ts` — counts `launching/` token files directly, does not reconcile against terminal run metadata
- `packages/dispatch-core/src/cleanup.ts` — should ideally recover stale launching tokens into the correct final state

## Suggested fix

1. Add a helper in `launch.ts` to rewrite `metadata/launch.json` at launch start, successful completion, rejected completion, and spawn failure.
2. Make `status.ts` filter out stale launching tokens when the token is expired, or a corresponding run has terminal `metadata/meta.json` with `status: completed|rejected`.
3. Optionally expose stale-launch counts separately in CLI output.

## Why this matters

The launcher itself may work, but the persisted dispatch state becomes inconsistent:

- run-local metadata says terminal
- token store says terminal
- `launch.json` still says launching
- CLI status can mislead operators into thinking an active launch still exists
