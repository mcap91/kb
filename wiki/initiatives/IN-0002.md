# IN-0002: Add kb-native planning records and execution bundles

## Summary

Add a first-class `PLN-*` planning artifact to `kb` for design-approved, one-time build work that
does not fit cleanly as either an initiative or a normal work item. The new type should keep
planning and execution-packaging material in the wiki as durable references while avoiding the
backlog noise and lifecycle mismatch that come from forcing this material into `IN-*`, `WK-*`, or
`HO-*`.

## Goals

- Define `PLN-*` as a manifest-driven wiki record for build scaffolds, not a second issue tracker.
- Define a normalized bundle layout under each `PLN-*` so `kb` owns the durable artifact shape
  regardless of which upstream planning tool produced the source material.
- Support adapter-based import from the current Superpowers brainstorming and `plan-me-this`
  workflow without hardcoding that workflow into the `kb` core contract.
- Keep `PLN-*` integrated with the rest of the wiki by reference, while excluding it from the
  standard work-tracking views by default.
- Dogfood the workflow on `kb` itself so future efforts can begin from `PLN-*` and only spawn
  `WK-*` records when concrete implementation or follow-up work appears.

## Notes

### Why This Exists

This initiative exists precisely because `IN-*` and `WK-*` are not the right long-term shape for
design-to-execution planning packs. We are using an initiative here only as bootstrap scaffolding
to deliver the `PLN-*` feature itself. Once `PLN-*` exists, future efforts should be able to start
from a plan record and only create `WK-*` items when execution reveals concrete tasks, defects, or
follow-up changes.

### Current Design Basis

The formal repo design for this feature is:

- [2026-05-06-pln-design.md](../../docs/superpowers/specs/2026-05-06-pln-design.md)
- [2026-05-06-pln-implementation.md](../../docs/superpowers/plans/2026-05-06-pln-implementation.md)

The current working and historical source planning material for this effort live in:

- [2026-05-04-kb-mvp-design.md](../../scratch_space/design/2026-05-04-kb-mvp-design.md)
- [IMPLEMENTATION_PLAN.md](../../scratch_space/plans/IMPLEMENTATION_PLAN.md)

The eventual `PLN-*` implementation should be able to normalize this sort of upstream material into
a canonical bundle without making the upstream tool the system of record.

### Scope Boundary

This initiative is intentionally narrow:

- no `EX-*` peer record type in the first pass
- no kb-native replacement for Superpowers brainstorming or `plan-me-this`
- no line-number-based cross-reference model as the canonical link mechanism
- no attempt to turn `PLN-*` into a second backlog or initiative system
